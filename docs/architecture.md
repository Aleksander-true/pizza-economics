# Архитектура

Игра разделена на данные, чистый движок, контроллер, интерфейс и сохранения. DOM и localStorage не входят в расчётный движок. Серверной части нет.

## Данные и расчёты

`src/engine/types.ts` задаёт контракты ингредиентов, рецептов, предложений, уровней, партий, результатов и прогресса.

`src/data/levels.ts` содержит 12 фиксированных сценариев и общий каталог рецептов. Цена принадлежит паре «рецепт + размер»; стоимость продуктов и новая поставка принадлежат определению дня (`LevelDefinition`). `Level` содержит фактический запас текущего раунда. Цены выводятся из цен 15 см, коэффициентов площади и скидок 2/6 монет на 30/45 см.

`Recipe.portions` — базовый состав 15 см. `Batch.portions` — фактические порции на одну пиццу выбранного размера. `SIZE_FACTORS` равны 1, 4 и 9. Движок умножает рецепт на коэффициент при распознавании, но повторно не умножает состав партии.

`src/engine/economy.ts` содержит:
- создание заготовки;
- проверку целых порций, количества, размера, распознавание рецепта, расход и стоимость;
- точный поиск оптимума по количествам доступных предложений с кешем оставшихся продуктов;
- оценку звёзд по итоговой прибыли относительно максимума.

`src/engine/inventory.ts` фиксирует входящие остатки и поставку в `RoundInventory`, затем собирает фактический `Level`. Поставка копируется при первом входе в новый день и не добавляется при повторе или перезагрузке.

Оптимизатор возвращает партии в том же формате фактических порций, который принимает оценка плана. Это сохраняет единый контракт для будущих подсказок и обязательных заказов.

## Контроллер

`src/app/controller.ts` управляет экранами `levels → planning → result`. UI отправляет типизированные команды и получает `Snapshot`. В снимке есть данные дня, план, оценка, оптимум, прогресс, заметки и очередь вводных подсказок.

Контроллер отвечает за:
- открытие текущего или следующего доступного дня и сброс черновика;
- состав, размер и количество партий;
- пропорциональное изменение порций при смене размера;
- платные расчёты и советы, скрытие устаревшего расчёта;
- начисление только улучшения личного рекорда;
- фиксацию лучшей попытки вместе с её остатками и перенос в следующий день;
- запрет повторов всех дней до текущего, независимо от состояния кнопок UI;
- запись заметок, подтверждённый сброс прогресса и ошибки сохранения;
- очередь ещё не просмотренных вводных подсказок.

Кеш оптимума учитывает номер дня и весь начальный запас. Это важно для переноса: одинаковый день может начаться с разными остатками. Приготовление сохраняет баланс, рекорд и остатки одним объектом прогресса. Равный или худший повтор оставляет лучшую попытку и её склад без изменений.

Новая игра открывает день 1. Просмотр подсказки не блокирует игровые команды и не требует заданных действий. UI временно показывает обычное закрываемое модальное окно.

## Вводные подсказки и карьера

`src/app/introductions.ts` содержит декларативные описания подсказок: идентификатор, первый день, заголовок, текст и смысловую цель. Там же движок рассчитывает прибыль двух планов для примера в блокноте по действующим ценам дня.

`src/ui/introductions.ts` показывает нативный `dialog`, выделяет цель, размещает окно относительно неё и отправляет команду закрытия. При недостатке места цель остаётся видимой, а содержимое окна прокручивается. Кнопки просмотра рецептов/блокнота необязательны.

`src/data/career.ts` определяет шесть должностей. В текущих сценариях доступны первые три; Пекарь начинается с 13-го дня, которого пока нет. Должность выводится из достигнутого открытого дня и не понижается при повторении. Доступные рецепты и размеры задаются данными конкретного дня.

Будущие закупки и смешанные составы пока не добавлены в движок. Для закупок согласован отдельный бюджет дня; ограничения бюджета и поставщика должны проверяться и в контроллере, и при поиске оптимума. Для смешанных пицц понадобится явный состав каждой половины/четверти, а не только суммарные порции. Правила дробных порций для разных размеров предстоит определить.

## Интерфейс

`src/ui/view.ts` рисует DOM и связывает ввод с командами. Выбор активной карточки — локальное состояние UI. Клик или касание выбирает карточку; Enter и пробел поддерживают выбор с клавиатуры. Наведение и смена фокуса не меняют выбор. Перенос через Pointer Events направляет продукт на любую часть конкретной карточки.

Подсветка нехватки использует глобальные остатки из оценки движка: UI отмечает ненулевые партии, расходующие дефицитный ингредиент, и выводит его общий недостающий объём. Произвольный приоритет между партиями не задаётся.

Карточки сохраняют свои DOM-узлы, пока их данные не меняются. Состав отображается в физических порциях, кнопки добавляют/убирают по одной. SVG в `art.ts` ограничивает слои сектором: четверть для 30 см, девятая для 45 см. Идентификаторы SVG-областей стабильны и различаются у партий и логотипа.

`notebook.ts` управляет свёрнутым `details` в шапке и размером текстовых ячеек. Пользовательский текст присваивается через `value`, не вставляется в HTML.

Бургер-меню использует нативный Popover API. Рецепты, возврат по логотипу и сброс используют `dialog.showModal()` с нативным фокусом и Escape. CSS переиспользует существующие токены и адаптивные сетки.

До покупки расчёта UI не выводит числовую прибыль. Видимые выручка и стоимость продуктов остаются исходными данными для самостоятельного счёта.

## Сохранения

`src/storage/progress.ts` проверяет localStorage и использует ключ `pizza-economics.progress.v3`. Сохранение содержит:
- общий баланс;
- `round`: текущий день, неизменные входящие остатки и поставка, а также прибыль, звёзды и остатки принятой лучшей попытки;
- лучшие звёзды и прибыль каждого дня;
- записи блокнота по дням;
- `seenFeatures` — идентификаторы просмотренных вводных подсказок.

При отсутствии v3 загружается v2 или v1. Числа запасов проверяются на целочисленность и неотрицательность; остатки результата не могут превышать начальный запас. Старые сохранения не содержат склада, поэтому контроллер оставляет деньги и записи, выбирает последний сыгранный день и фиксирует для него новую поставку без входящих остатков. Отметка миграции объясняет это в меню. Для перехода дальше нужен результат уже этого запаса. Исторические деньги уровня 0 сохраняются.

При ошибке записи игра продолжает работать в памяти и показывает предупреждение. Сброс сначала сохраняет чистое состояние; только после успешной записи контроллер заменяет текущую игру.

## Проверки и ограничения

Только смоук-проверки, без модульного тестового фреймворка. Типы и сборка проверяются через `npm run build`. Внешние смоук-сценарии проходят 12 дней с оптимальными и минимальными планами, проверяют сохранение общего количества продуктов, единственную поставку, запрет старых дней, лучший/равный/худший повтор, перезагрузку, старые сохранения и сброс. Интерфейс проверяется в Яндекс Браузере через отдельный профиль.

Смоук не подтверждает педагогический баланс для детей или работу на физическом планшете. Количество сценариев и запасов сейчас небольшое; при существенном расширении нужно отдельно измерить время поиска оптимума.
